# Irodoriの本文内絵文字制御

## 読み上げ時の手順

1. 実際のproviderとcheckpointを確認する。公式のv4.1 Smallは絵文字による表現制御を継承し、speech.cpp v0.8.4のIrodori実装も対応する注釈を保持する。provider名だけで他のモデルまで対応と判断しない。
2. 基盤、参照音声・話者埋め込み・LoRA、voice、速度、seedを保ち、意図する表現に合う注釈を本文へ1個加える。声の作り直しやstyleの自動生成は不要。発話内容や本人の指定していない感情は勝手に変えない。
3. 注釈は台詞と同じ行に置く。たとえば `👂 ここだけ、小さな声で話すね。`。句中で間を狙う例は `少し待って。⏸️ 大丈夫。`。全体への厳密な適用範囲や、指定秒数の無音を保証する構文ではない。
4. OpenClawを通す場合は本文整形後にも注釈が残ることを確かめる。送信される `input` と生成結果を別々に検証する。音声生成が成功しても、囁きや笑いの聴感を確認したことにはしない。

## 入れる場所

- 公式Irodori API: `POST /v1/audio/speech` の `input`。同梱providerではリクエストの `text` が `input` へ渡る。
- speech.cpp API: 同じく `input`。対応するIrodoriモデルを使用する。絵文字専用の追加フィールドは作らない。
- 制作wrapper: `audition --text` / `--texts` の台詞に含める。captionは全体の表現説明、本文中の注釈は発話の表現指示として区別する。
- OpenClawで表示文と読み上げ文を分ける場合は `[[tts:text]]👂 ここだけ、小さな声で話すね。[[/tts:text]]` のように読み上げ用本文へ入れる。自動読み上げがoffなら、この記法を追加するために勝手にonへ変えない。

手動で試す例:

```text
/tts audio 👂 ここだけ、小さな声で話すね。
/tts audio 🤭 それは面白いね。
/tts audio 🫶 ゆっくりでいいよ。
/tts audio 少し待って。⏸️ 大丈夫。
```

`caption` や `instructions` は絵文字の必須ラッパーではない。自然文による全体指定が必要なら、公式APIの `irodori.caption`、speech.cppの `instructions` をそれぞれ使う。SBV2の `style` / `style_weight` と混同しない。

## OpenClawの本文整形に関する制限

公式は同じ絵文字の繰り返しで効果を強められるとしている。ただしモデルに届く前の装飾除去は別問題。確認したOpenClawの `normalizeSpeechText` → `stripMarkdown(..., {mode: "speech"})` 経路では次の結果になった。

| 入力 | 整形後 |
| --- | --- |
| `👂 ここだけ小さな声で話すね。` | 絵文字を保持 |
| `🤭 よかったね。` | 絵文字を保持 |
| `🤭🤭 よかったね。` | `よかったね。` |
| `🤭` だけの行 + 次の行の台詞 | 絵文字だけの行を削除 |
| `少し待って。⏸️ 大丈夫。` | 絵文字を保持 |
| `😮‍💨 ふう。` | ZWJを含む絵文字を保持 |

2026-10-17には、公式実装の注釈リスト全56種についても、1個ずつ通常文の先頭に置いて実際の `normalizeSpeechText` に通し、56/56が元のUnicode表記のまま残ることを確認した。これは本文通過の確認であり、全56種の音声効果を試聴した結果ではない。

これは確認したホスト実装の挙動であり、将来版や別クライアントにも固定の仕様とは扱わない。通常は単独注釈を台詞と同じ行に置く。繰り返しの用法を使うなら、その経路での通過を先に確認する。プラグインのproviderが受け取った本文から、既に失われた絵文字を復元できるとは言わない。ホスト側の装飾除去を黙って改変したり、未対応を対応済みと報告したりしない。

公式表の表記をそのまま使い、`😮‍💨` のZWJや `⏸️` のvariation selectorを削らない。絵文字を別の見た目の記号・日本語の感情名・独自タグへ勝手に置き換えない。表示用の装飾絵文字と、モデルへ伝える注釈を区別する。

## 実装にのみある追加11種

公式Irodoriの `irodori_tts/duration.py` にある `ALLOWED_ANNOTATION_EMOJIS` は全56種で、上の45種をすべて含む。speech.cpp v0.8.4のモデル文書も56種としている。差分は以下の11種で、表記ゆれやvariation selector違いではなく別の絵文字である。

| 絵文字 | 公式対応表での意味 |
| --- | --- |
| ⏱️ | 未記載 |
| 🍭 | 未記載 |
| 🎛️ | 未記載 |
| 🎭 | 未記載 |
| 🐱 | 未記載 |
| 👏 | 未記載 |
| 💦 | 未記載 |
| 📄 | 未記載 |
| 📣 | 未記載 |
| 🤢 | 未記載 |
| 🥹 | 未記載 |

この定数はduration featureの注釈数カウントにも使われる。実装で注釈として数えることや本文を通過することは、対応表にない意味・音声効果を保証しない。全種を尋ねられたら「意味が公開されている45種 + 実装リストにのみある11種 = 56種」と区別し、11種の効果を見た目から創作しない。通常の表現指定は意味の分かる45種から選ぶ。

## 検証と記録

試す場合は、注釈なしと単独注釈ありの短い同文を、同じ基盤・voice・seedで比較する。本文がAPIへ届いたこと、WAVが作れたこと、本人が表現を聴き取れたことを分けて記録する。依頼がスキル整備だけなら、追加合成・学習・既定声切替を始めない。効果が弱くても直ちに話者の不採用や再学習へ飛ばない。
